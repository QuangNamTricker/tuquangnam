1.1Tháp Hà Nội

Đệ quy cơ bản · T(n) = 2ⁿ − 1 · O(2ⁿ) thời gian, O(n) bộ nhớ

Phát biểu bài toán

Có 3 cọc A, B, C. Cọc A có n đĩa kích thước khác nhau, đĩa lớn nằm dưới. Cần chuyển toàn bộ n đĩa sang cọc C, dùng B làm trung gian. Ràng buộc: mỗi lần chỉ chuyển 1 đĩa trên cùng, và không bao giờ đặt đĩa lớn lên đĩa nhỏ.

Input: n (0 ≤ n ≤ 20)  ·  Output: dãy bước chuyển + tổng số bước

Cách giải — ý tưởng đệ quy

Gọi HN(n, A, B, C) là thao tác chuyển n đĩa từ A sang C, dùng B làm trung gian.

  • Trường hợp cơ sở: n = 0 → không có gì để chuyển, dừng.
  • Bước đệ quy gồm 3 thao tác:
    1. Chuyển n−1 đĩa trên cùng từ A sang B (dùng C trung gian) → HN(n−1, A, C, B).
    2. Chuyển đĩa lớn nhất (đĩa thứ n) từ A sang C → in bước chuyển.
    3. Chuyển n−1 đĩa từ B sang C (dùng A trung gian) → HN(n−1, B, A, C).
Vì sao đúng? Sau bước 1, n−1 đĩa nhỏ đã nằm gọn trên B → đĩa lớn nhất ở A là đĩa duy nhất còn lại, chuyển thẳng sang C không vi phạm quy tắc. Sau bước 2, đĩa lớn nhất đã ở đúng vị trí cuối cùng dưới đáy C → bước 3 chỉ cần chuyển n−1 đĩa từ B sang C.

Công thức số bước

T(n) = 2·T(n−1) + 1,   T(0) = 0   ⟹   T(n) = 2ⁿ − 1
Vì sao tối ưu? Đĩa lớn nhất buộc phải chuyển ít nhất 1 lần; trước đó phải đưa n−1 đĩa ra khỏi A, sau đó đưa n−1 đĩa về C → T(n) ≥ 2·T(n−1)+1. Thuật toán đạt đúng cận này.

1.2Tổ hợp C(n,k) & kỹ thuật ghi nhớ

Đánh đổi bộ nhớ lấy thời gian · 310 triệu lần gọi vs 225 ô

Phát biểu bài toán

Tính số tổ hợp chập k của n phần tử theo công thức Pascal, và so sánh hai cách cài đặt: đệ quy thuần và đệ quy có ghi nhớ (memoization).

Input: n, k (0 ≤ k ≤ n ≤ 30)  ·  Output: C(n,k), số lần gọi hàm bản thuần, số ô thực sự tính của bản ghi nhớ

Cách giải — công thức Pascal

C(n,0) = C(n,n) = 1  ·  C(n,k) = C(n−1,k−1) + C(n−1,k)

Cách 1 – đệ quy thuần: viết đúng công thức trên. Nhược điểm: cùng một ô C(i,j) bị tính lại rất nhiều lần — số lần gọi = 2·C(n,k) − 1, tăng theo hàm mũ.

Cách 2 – ghi nhớ: thêm mảng memo[n][k] và mảng daTinh[n][k]. Khi cần C(n,k): nếu ô đã tính → trả về ngay memo[n][k]; nếu chưa → tính, lưu vào memo, đánh dấu. Nhờ vậy mỗi ô chỉ tính đúng một lần.

Vì sao bản thuần gọi 2·C(n,k) − 1 lần? Mỗi lần gọi không phải cơ sở sinh ra 2 lần gọi con. Cây gọi có C(n,k) lá (ô cơ sở) → tổng số nút = 2·lá − 1.

Minh họa C(5,2) = 10

Bản thuần gọi 2·10 − 1 = 19 lần. Bản ghi nhớ chỉ tính 6 ô không phải ô cơ sở:

Thứ tựÔ (n,k)Giá trịCách tính

2(3,1)3C(2,0) + C(2,1) = 1 + 2
3(4,1)4C(3,0) + C(3,1) = 1 + 3
4(3,2)3C(2,1) + C(2,2) = 2 (đọc lại) + 1
5(4,2)6C(3,1) (đọc lại) + C(3,2) = 3 + 3
6(5,2)10C(4,1) + C(4,2) = 4 + 6

Cài đặt (P1_Bai02.cpp)

long long C1(int n, int k) {          // đệ quy thuần
    goiThuan++;
    if (k == 0 || k == n) return 1;
    return C1(n - 1, k - 1) + C1(n - 1, k);
}

long long C2(int n, int k) {          // đệ quy có ghi nhớ
    if (k == 0 || k == n) return 1;
    if (daTinh[n][k]) return memo[n][k];
    daTinh[n][k] = true;
    soOTinh++;
    return memo[n][k] = C2(n - 1, k - 1) + C2(n - 1, k);
}

1.3Liệt kê hoán vị bằng quay lui

Thử – đánh dấu – đệ quy – gỡ đánh dấu · O(n·n!)

Phát biểu bài toán

Liệt kê tất cả hoán vị của tập {1, 2, …, n} theo thứ tự từ điển.

Input: n (1 ≤ n ≤ 8)  ·  Output: mỗi dòng một hoán vị, cuối cùng in tổng số (bằng n!)

Cách giải — quay lui

Xây dựng hoán vị từng vị trí. Tại vị trí i, thử lần lượt các giá trị v từ 1 đến n chưa được dùng:

  1. Gán x[i] = v, đánh dấu dung[v] = true.
  2. Nếu i = n → in kết quả; ngược lại gọi đệ quy Thu(i+1).
  3. Quay lui: gỡ đánh dấu dung[v] = false để thử giá trị khác.
Vì sao phải gỡ đánh dấu? Sau khi in xong một hoán vị và quay về vị trí trước, giá trị v phải được "giải phóng" để dùng lại ở nhánh khác. Nếu không gỡ, các hoán vị sau sẽ thiếu giá trị.

Cài đặt (P1_Bai03.cpp)

void thu(int i) {
    for (int v = 1; v <= n; v++) {
        if (!dung[v]) {
            x[i] = v;
            dung[v] = true;
            if (i == n) inKetQua();
            else thu(i + 1);
            dung[v] = false;      // quay lui
        }
    }
}

1.4Khử đệ quy bằng ngăn xếp

Thay lời gọi hàm bằng frame · O(2ⁿ) thời gian, O(n) bộ nhớ

Phát biểu bài toán

Cài đặt lại Tháp Hà Nội không dùng đệ quy, thay bằng một ngăn xếp tự cài để thay cho ngăn xếp gọi hàm của hệ thống. Kết quả phải giống hệt bản đệ quy.

Input: n (0 ≤ n ≤ 20)  ·  Output: dãy bước chuyển + tổng số bước, giống mục 1.1

Cách giải — thay lời gọi bằng frame

Mỗi lời gọi đệ quy được thay bằng một khung (frame) lưu trong ngăn xếp. Có 2 loại khung:

  • Khung S(n, a, b, c): việc "giải bài toán n đĩa từ a sang c qua b".
  • Khung M(d, a→c): việc "chuyển đĩa d từ a sang c".

Vòng lặp: lấy khung ở đỉnh ra.

  • Nếu là M → in bước chuyển.
  • Nếu là S với n > 0 → đẩy vào 3 khung theo thứ tự ngược để khung xử lý đầu tiên nằm trên đỉnh: đẩy S(n−1, b, a, c), rồi M(n, a→c), rồi S(n−1, a, c, b).
  • Khung S với n = 0 bị bỏ qua. Ngăn xếp rỗng thì dừng.
Vì sao đẩy 3 khung theo thứ tự ngược? Ngăn xếp là LIFO: khung đẩy sau cùng sẽ được lấy ra đầu tiên. Ta muốn xử lý theo thứ tự (1) S(n−1,a→b), (2) M(n,a→c), (3) S(n−1,b→c) — nên phải đẩy ngược: (3) trước, rồi (2), rồi (1) để (1) nằm trên đỉnh.

Cài đặt (P1_Bai04.cpp)

struct Frame {
    int loai;      // 0: S (giải bài toán), 1: M (chuyển đĩa)
    int n;         // số đĩa (loại 0) hoặc số hiệu đĩa (loại 1)
    char a, b, c;  // cọc nguồn, trung gian, đích
};

while (top >= 0) {
    Frame f = st[top--];
    if (f.loai == 1) {           // khung M: in bước chuyển
        dem++;
        cout << "Buoc " << dem << ": chuyen dia " << f.n
             << " tu " << f.a << " sang " << f.c << endl;
    } else if (f.n > 0) {     // khung S: đẩy 3 khung ngược
        push({0, f.n - 1, f.b, f.a, f.c});   // làm sau cùng: B → C
        push({1, f.n, f.a, f.b, f.c});       // chuyển đĩa n: A → C
        push({0, f.n - 1, f.a, f.c, f.b});   // làm đầu tiên: A → B
    }
}

★Cách giải chi tiết (để hiểu sâu)

Giải thích sâu hơn — dùng khi trả lời câu hỏi hoặc cần nắm bản chất

B.1. Tháp Hà Nội — vì sao T(n) = 2ⁿ − 1 là tối ưu?

  • Đĩa lớn nhất (đĩa n) buộc phải chuyển từ A sang C ít nhất 1 lần.
  • Trước khi chuyển nó, n−1 đĩa nhỏ phải nằm gọn trên B → tốn ít nhất T(n−1) bước.
  • Sau khi chuyển nó, n−1 đĩa phải từ B sang C → tốn ít nhất T(n−1) bước.
  • Vậy T(n) ≥ 2·T(n−1) + 1. Thuật toán đạt đúng cận này → tối ưu.

Cây gọi n = 3:

HN(3,A,B,C)
├── HN(2,A,C,B)
│   ├── HN(1,A,B,C): đĩa1 A→C
│   ├── đĩa2 A→B
│   └── HN(1,C,A,B): đĩa1 C→B
├── đĩa3 A→C
└── HN(2,B,A,C)
    ├── HN(1,B,C,A): đĩa1 B→A
    ├── đĩa2 B→C
    └── HN(1,A,B,C): đĩa1 A→C

Bấm vào từng câu để xem câu trả lời gợi ý

Q1: Vì sao T(n) = 2ⁿ − 1 là số bước nhỏ nhất?
Vì đĩa lớn nhất buộc phải chuyển ít nhất 1 lần; trước đó phải đưa n−1 đĩa ra khỏi A, sau đó đưa n−1 đĩa về C → T(n) ≥ 2·T(n−1)+1. Thuật toán đạt đúng cận → tối ưu.
Q2: Memoization khác gì quy hoạch động?
Memoization là đệ quy top-down kèm cache — chỉ tính ô thực sự cần. Quy hoạch động là bottom-up — điền cả bảng từ nhỏ đến lớn. Cùng độ phức tạp nhưng memoization chỉ tính ô cần thiết.
Q3: Vì sao phải "gỡ đánh dấu" ở bài hoán vị?
Vì sau khi quay lui, giá trị đó phải được giải phóng để dùng lại ở nhánh khác. Nếu không gỡ, các hoán vị sau sẽ thiếu giá trị.
Q4: Khử đệ quy có lợi gì khi độ phức tạp không đổi?
Kiểm soát bộ nhớ, tránh tràn ngăn xếp hệ thống khi độ sâu lớn; đồng thời giúp hiểu cơ chế đệ quy bên dưới.
Q5: Nếu n = 20 thì Tháp Hà Nội mất bao nhiêu bước?
2²⁰ − 1 = 1.048.575 bước. Chương trình vẫn chạy nhưng in rất nhiều dòng — đây là lý do giới hạn n ≤ 20.
Q6: Vì sao đẩy 3 khung theo thứ tự ngược ở bài 1.4?
Vì ngăn xếp là LIFO: khung đẩy sau cùng được lấy ra đầu tiên. Muốn xử lý S(n−1,a→b) trước thì phải đẩy nó sau cùng.
Q7: Bản ghi nhớ bài 1.2 có thể bị tràn bộ nhớ không?
Với n ≤ 30, mảng 31×31 là rất nhỏ (~7.5KB cho long long), không đáng kể. Nếu n lớn hơn nhiều thì cần cân nhắc.
Q8: Bài 1.4 có thể áp dụng cho bài nào khác không?
Có — mọi giải thuật đệ quy đều có thể khử bằng ngăn xếp tự cài theo cùng nguyên tắc: thay lời gọi bằng frame, đẩy ngược thứ tự.
